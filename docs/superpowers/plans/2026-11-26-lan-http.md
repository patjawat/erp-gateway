# LAN HTTP Implementation Plan

> Implement in this session with bounded parallel file ownership; do not create worktrees or install additional skills.

**Goal:** Enable explicitly configured LAN HTTP for Setup and Admin at the user's private IP.

**Architecture:** A shared web transport policy enforces private URL, direct peer CIDR, Host and Origin rules. Bootstrap and runtime consume this policy; the frontend reads a capability flag. Existing HTTPS remains the default.

**Tech Stack:** Go, Angular/TypeScript, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-26-lan-http-design.md`

## Global Constraints

- No ERP writes, service restarts, volume migration, dependency installation or simulator execution.
- Keep upstream HTTPS/mTLS, identity, database and encryption key behavior intact.
- Use `GATEWAY_ALLOW_LAN_HTTP` and `GATEWAY_LAN_HTTP_CIDRS`; metadata is `lan_http_enabled`.
- User approved the HTTP LAN approach; proceed without another execution approval.

## Review Focus

- A forged forwarded header or public/unlisted peer must not grant HTTP access.
- Missing mode/allowlist after restart must not silently enable a stored HTTP URL.
- Settings changes and recovery must follow the same validation as first setup.
- HTTP cookie/Origin handling must work through activation and Admin login.
- Frontend capability handling must preserve HTTPS validation when the flag is absent.

### Task 1: Transport policy and bootstrap

Files: create `backend/internal/webtransport/policy.go` and tests; update bootstrap config/manager/settings/recovery and focused tests.

Interface: `webtransport.New(bool, []string) (Policy, error)`, `Policy.ValidateURL(string) (*url.URL, error)`, `Policy.LANHTTPEnabled() bool`, `Policy.IsLANHTTPURL(string) bool`, `Policy.AllowsLANRequest(*http.Request, string) bool`, `Policy.AllowsLANOrigin(*http.Request, string) bool`; `bootstrap.Options.WebPolicy`.

- [x] Test enabled private HTTP and reject public URLs, invalid CIDRs, unlisted peers, wrong Host/Origin and spoofed forwarded headers.
- [x] Apply one policy to bootstrap input, persisted config, settings and recovery; expose metadata and configured setup URL without secrets.
- [x] Test HTTP setup/session/activation/reload/settings/recovery and unchanged default HTTPS behavior.

### Task 2: Runtime and deployment configuration

Files: gateway server/admin/settings and tests, main startup, root Compose, `.env.example`, README and WEB_SETUP.

- [x] Parse the explicit opt-in and require the private allowlist; errors name the environment variable without printing secrets.
- [x] Pass the policy through bootstrap/runtime/restore; guard LAN Admin requests and derive secure cookies from the validated runtime URL.
- [x] Test Admin login, cookies, CSRF, peer/Host denial and HTTPS regression.
- [x] Document exact `.env` values for port 8080, binding 10.10.8.127 and allowlist 10.10.8.0/24, plus required source image rebuild.

### Task 3: Existing forms and final validation

Files: existing embedded Setup/Settings assets and Angular management models/page/tests.

- [x] Consume `lan_http_enabled`; show plaintext-mode copy and private HTTP URL examples only in this mode.
- [x] Test flag absent/disabled, private HTTP allowed, public HTTP rejected and unchanged hospital HTTPS validation.
- [x] Run relevant Go tests/vet and Angular checks/build. Validate resolved Compose securely and check scoped diff.

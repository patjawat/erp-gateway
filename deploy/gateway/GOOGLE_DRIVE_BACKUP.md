# สำรอง Gateway ไปยัง Google Drive ส่วนตัว

Gateway ใช้บัญชี Gmail ของผู้ดูแลผ่าน Google OAuth และโฟลเดอร์ที่แอปสร้างสำหรับไฟล์สำรอง ใช้สิทธิ์ `drive.file` เพื่อจัดการไฟล์ของการเชื่อมต่อนี้ ไม่ขอสิทธิ์อ่านอีเมลหรือค้นไฟล์ส่วนตัวทั้ง Drive

การกด **สำรองข้อมูลตอนนี้** และดาวน์โหลดไฟล์ยังใช้ได้โดยไม่เชื่อม Google Drive ส่วนการสำรองอัตโนมัตินอกเครื่องต้องเชื่อมบัญชีตามขั้นตอนนี้ก่อน เครื่องเซิร์ฟเวอร์ไม่ต้องติดตั้ง Restic, rclone หรือ cron เอง เพราะรวมเครื่องมือไว้ใน Docker image แล้ว

## 1. เตรียม Google OAuth ของผู้ดูแล

1. เปิด [Google Cloud Console](https://console.cloud.google.com/) และเลือกหรือสร้างโปรเจกต์สำหรับ Gateway
2. เปิดใช้งาน **Google Drive API** ใน API Library
3. ตั้งค่า Google Auth Platform / OAuth consent screen โดยระบุชื่อแอป อีเมลติดต่อ และกลุ่มผู้ใช้ **External** สำหรับบัญชี Gmail ส่วนตัว
4. เพิ่มสิทธิ์ `https://www.googleapis.com/auth/drive.file` ใน Data Access ไม่จำเป็นต้องใช้สิทธิ์ Drive ทั้งบัญชี
5. สร้าง OAuth client ชนิด **Web application** เก็บ Client ID และ Client secret ไว้ในที่ที่ผู้ดูแลเข้าถึงได้
6. เพิ่ม **Authorized redirect URI** ให้ตรงกับ URL callback ที่แสดงในหน้าการเชื่อมต่อ Google Drive ของ Gateway รวม scheme, hostname, port และ path ให้ตรงทั้งหมด

ตัวอย่าง callback สำหรับเซิร์ฟเวอร์ที่มี HTTPS:

```text
https://gateway.example.org/backup/oauth/callback
```

ตัวอย่างสำหรับทดสอบที่ Mac โดย Gateway เปิดที่พอร์ต 8080:

```text
http://127.0.0.1:8080/backup/oauth/callback
```

เปลี่ยนพอร์ตให้ตรงกับเครื่องจริง และลงทะเบียน URL ที่ใช้จริงใน Google ก่อนเชื่อม ไม่ใช้ URL ตัวอย่างโดยไม่แก้ไข Google ไม่รับ arbitrary LAN HTTP callback เช่น `http://10.10.8.127:8080/...` ในขั้นตอนนี้

**เมื่อใช้งานจริง:** External OAuth app ที่คงสถานะ **Testing** อาจได้รับ refresh token อายุเพียง 7 วันเมื่อขอสิทธิ์ Drive ให้เปลี่ยนเป็น **Production** และทำข้อกำหนด/การตรวจสอบที่ Google แสดงสำหรับโปรเจกต์นั้น ระหว่างพัฒนาใน Testing ให้เพิ่ม Gmail ของผู้ดูแลในรายชื่อ Test users และเตรียมเชื่อมบัญชีใหม่เมื่อ token หมดอายุ การตั้งค่า OAuth ไม่ทำให้สิทธิ์เข้าบัญชี Google เกิดขึ้นเอง ผู้ดูแลยังต้องกดยินยอมด้วยบัญชีของตน

## 2. เชื่อมบัญชีผ่าน Gateway

1. เข้าสู่ระบบผู้ดูแล แล้วเปิดหน้า **สำรองข้อมูลและย้ายเครื่อง**
2. เปิดการเชื่อมต่อ Google Drive ระบุ Client ID, Client secret และ redirect URI ของโปรเจกต์ที่เตรียมไว้
3. กดเชื่อมต่อ แล้วลงชื่อเข้าใช้ Gmail ที่จะเก็บข้อมูลสำรอง ยืนยันสิทธิ์บนหน้าของ Google
4. เมื่อกลับเข้า Gateway ให้ตรวจสถานะการเชื่อมต่อและโฟลเดอร์สำรอง ระบบสร้างหรือใช้โฟลเดอร์ **ERP Gateway Backups** ของ OAuth client นี้ และแบ่ง repository ตามชุดข้อมูลของ Gateway
5. เลือกปลายทางเป็น **ในเครื่องและ Google Drive** กำหนดรอบสำรองและจำนวนชุดที่เก็บ เริ่มต้นรอบละ 15 นาทีและปรับได้

Client secret และ token เป็นข้อมูลลับ Gateway เก็บการเชื่อมต่อแบบเข้ารหัส ไม่ต้องนำ refresh token ไปใส่ใน `.env`, คำสั่ง shell หรือส่งให้ผู้อื่น การยกเลิกการเชื่อมต่อหยุดการใช้งานบัญชีนั้น แต่ไม่ลบไฟล์สำรองเดิมใน Drive

## 3. ตรวจว่าการสำรองนอกเครื่องทำงานจริง

กด **สำรองข้อมูลตอนนี้** แล้วรอจนสถานะ Google Drive แสดงเวลาส่งสำเร็จที่ตรวจสอบแล้ว สถานะสำรองในเครื่องสำเร็จเพียงอย่างเดียวยังไม่แปลว่าไฟล์ถึง Drive หากการส่งล้มเหลว ไฟล์สำรองในเครื่องที่ตรวจสอบผ่านยังคงดาวน์โหลดได้

การทดสอบอัตโนมัติใน repository ใช้บริการ OAuth/Drive จำลองเพื่อทดสอบการต่ออายุ token การเพิกถอนสิทธิ์ โควตา และกรณีผิดพลาด ต้องตรวจการยินยอมและการส่งไฟล์ด้วยบัญชีจริงของเจ้าของอีกครั้งหลังตั้งค่า ไม่ถือว่าผลทดสอบจำลองเป็นหลักฐานว่าเชื่อม Gmail จริงแล้ว

ดาวน์โหลด **ชุดกู้คืน** และเก็บแยกจากไฟล์สำรอง เช่น password manager หรือสื่อสำรองนอกเครื่องเดิม ชุดนี้มีความลับสำหรับเปิดไฟล์สำรองและข้อมูล OAuth client ที่จำเป็นต่อการกู้คืน ห้ามอัปโหลดแบบไม่เข้ารหัสไว้ข้าง repository เดียวกัน และไม่ควรเก็บสำเนาไว้ที่เครื่องเดิมเพียงแห่งเดียว

## 4. เมื่อต้องกู้คืนบนเครื่องใหม่

ใช้ Docker image/ซอร์สของ Gateway ที่รองรับรูปแบบข้อมูลสำรอง แล้วใช้ไฟล์สำรองพร้อมกุญแจกู้คืน หรือเชื่อมบัญชี Google อีกครั้งด้วย **OAuth client เดิม** และข้อมูลในชุดกู้คืน การกู้คืนจาก Drive ไม่ต้องอาศัย refresh token ที่อยู่เฉพาะเครื่องที่เสียไป แต่ต้องมีสิทธิ์ลงชื่อเข้า Gmail เจ้าของโฟลเดอร์นั้น

การลืมรหัสผ่านผู้ดูแล Gateway แก้ด้วย `setup-password` ได้ แต่คำสั่งนั้นไม่สร้างกุญแจเปิดไฟล์สำรองที่สูญหายขึ้นใหม่ การสำรองนี้ครอบคลุมข้อมูล Gateway ส่วนฐานข้อมูล ERP และ private key ของ CA ที่เก็บบน Mac ต้องมีแผนสำรองแยกต่างหาก

ตรวจใบรับรอง client, URL ปลายทาง ERP และ public endpoint หลังนำเข้า การเปลี่ยนเครื่องไม่ทำให้ใบรับรองที่หมดอายุกลับมาใช้ได้ หรือเปลี่ยน URL ที่ Mobile เรียกโดยอัตโนมัติ

## Callback สำหรับเซิร์ฟเวอร์ภายใน/ผ่าน SSH tunnel

หาก Gateway ไม่มี HTTPS callback ที่ Google เข้าถึงผ่านเบราว์เซอร์ของผู้ดูแลได้ ให้ใช้โดเมน HTTPS ผ่าน reverse proxy หรือ callback แบบ loopback ผ่าน SSH tunnel แทนการลงทะเบียน HTTP LAN IP

ตัวอย่างเปิด tunnel จาก Mac ไปยัง Gateway ที่รับบน `127.0.0.1:8080` ของเซิร์ฟเวอร์:

```bash
ssh -N -L 18080:127.0.0.1:8080 user@your-server
```

ลงทะเบียนและระบุ redirect URI เป็น `http://127.0.0.1:18080/backup/oauth/callback` ให้ตรงกัน และเปิด tunnel ค้างไว้จนการยินยอมเสร็จ พอร์ตขาเข้าของ SSH, พอร์ต Gateway ที่เครื่องปลายทาง และนโยบายการเข้าหน้า Admin ต้องตรงกับสภาพแวดล้อมจริง การเปิด tunnel ไม่เปลี่ยนนโยบายเข้าถึงหน้า Admin ที่ตั้งค่าไว้อยู่แล้ว

## เมื่อเชื่อมต่อหรือส่งไฟล์ไม่สำเร็จ

- **Google แจ้ง redirect URI mismatch:** เทียบ URL ใน Gateway กับ Authorized redirect URI รวม HTTP/HTTPS, port และ path
- **ต้องเชื่อมใหม่ทุกประมาณ 7 วัน:** ตรวจสถานะ OAuth app ว่ายังอยู่ใน Testing หรือไม่
- **สิทธิ์ถูกเพิกถอน/บัญชีเชื่อมต่อหมดอายุ:** เชื่อม Gmail เจ้าของอีกครั้งกับ OAuth client เดิม
- **Drive เต็มหรือเกินโควตา:** ตรวจพื้นที่บัญชีและช่วงเวลาสำรอง ไฟล์สำรองที่ดีเดิมจะไม่ถูกลบเพื่อกลบข้อผิดพลาด
- **ไม่พบโฟลเดอร์เดิมหลังย้ายเครื่อง:** ตรวจ Gmail, OAuth client และ Folder ID จากชุดกู้คืน การเปลี่ยน client อาจทำให้สิทธิ์ `drive.file` มองไม่เห็นโฟลเดอร์ที่ client เดิมสร้าง

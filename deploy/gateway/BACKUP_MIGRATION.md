# สำรองข้อมูล กู้คืน และย้ายเครื่อง Gateway

ใช้เมนู **สำรองข้อมูลและย้ายเครื่อง** (`/admin/backups`) ของ Gateway รุ่นที่มีฟีเจอร์นี้ Docker image รวม Restic และ rclone ที่ตรวจ checksum ไว้แล้ว ไม่ต้องติดตั้งเครื่องมือบน host เพิ่ม ไม่ใช้ Docker socket หรือ cron บน host

## ข้อมูลที่เก็บ

ไฟล์สำรองเข้ารหัสรวม SQLite ของ Gateway: หน่วยงาน ปลายทาง ERP สิทธิ์/สถานะ ประวัติ สถิติ Mobile sessions และข้อมูลยืนยันตัวตนที่ Gateway เก็บ พร้อมบัญชีผู้ดูแลเดิม encryption key ใบ client และ private key ของ Gateway, Hospital server CA และ FCM/การเชื่อม Drive ที่ตั้งไว้

ไม่รวมฐานข้อมูล/ไฟล์ของ ERP แอป Mobile ซอร์สโค้ด Docker images หรือกุญแจลงนาม CA ที่เก็บแยกบน Mac ต้องสำรองสิ่งเหล่านั้นต่างหาก ไฟล์ config-recovery v1 เดิมยังใช้ได้ แต่เป็น config-only ไม่ใช่ไฟล์สำรองครบชนิดใหม่นี้

## สำรองและดาวน์โหลดตอนนี้

1. เข้าระบบผู้ดูแล เปิด **สำรองข้อมูลและย้ายเครื่อง** แล้วกด **สำรองข้อมูลตอนนี้**
2. ระบบสร้าง snapshot ขณะ Mobile ยังใช้งานได้ แล้วตรวจฐานข้อมูลและเข้ารหัส
3. เมื่อไฟล์ในเครื่องพร้อม กดดาวน์โหลดได้แม้กำลังอัปโหลด Drive หาก Drive ล้มเหลว ไฟล์ในเครื่องที่ตรวจแล้วจะยังอยู่ตามนโยบายเก็บ
4. ดาวน์โหลด **ชุดกู้คืน** ที่คู่กับรายการนั้นด้วย เก็บแยกจากไฟล์สำรอง เช่น password manager หรืออุปกรณ์สำรองอีกชิ้น อย่าอัปโหลดกุญแจนี้ไว้ข้างไฟล์สำรองแบบไม่เข้ารหัส

ชุดกู้คืนเป็นไฟล์กุญแจสุ่ม ไม่ต้องจำรหัสใหม่หรือใช้รหัสผ่าน Admin กุญแจหายทุกสำเนาแล้วจะเปิดไฟล์สำรองไม่ได้ การรีเซ็ตรหัสผ่าน Admin ไม่ได้กู้กุญแจสำรองกลับมา

รุ่นนี้จำกัดชุดนำเข้า/โอนตรงไว้ที่ 16 GiB และต้องมีพื้นที่สำหรับ staging กับ rollback แยกจากฐานข้อมูลที่ใช้งานอยู่ ระบบจะหยุดหากพื้นที่ไม่พอ โดยไม่เริ่มฐานข้อมูลว่างแทน

ไฟล์เก็บข้อมูลถึง **เวลาที่สำรอง** การเปลี่ยนแปลงหลังจากนั้นไม่ได้ติดไปด้วย การย้ายระบบที่ยังใช้งานอยู่ให้ใช้ขั้นตอนเก็บข้อมูลชุดสุดท้ายด้านล่าง

## นำเข้าเครื่องใหม่

1. เตรียมโค้ด/Compose หรือ image ที่รองรับสถาปัตยกรรมเซิร์ฟเวอร์ อย่านำ image ของ Mac ไปใช้โดยสมมติว่า CPU ตรงกัน
2. เริ่ม Gateway เครื่องใหม่ด้วย `docker compose up -d` และ `SETUP=true` ในช่วงติดตั้ง
3. เปิด `/setup/` ยืนยันรหัส Setup ที่ออกจากเครื่องใหม่ แล้วเลือก **นำเข้าข้อมูล Gateway เดิม**
4. เลือกไฟล์ `.bundle` และใส่กุญแจหรือเนื้อหาไฟล์ชุดกู้คืน กำหนด URL ของปลายทางให้เข้าถึงได้จริง
5. ตรวจเวลา ข้อมูลสรุป ใบรับรอง และ URL ก่อนยืนยัน **ต้นทางหยุดแล้ว** และเปิดใช้งาน อย่าเปิด Gateway สองเครื่องด้วยข้อมูลชุดเดียวกัน

ระบบตรวจและเตรียมไฟล์ในพื้นที่ส่วนตัวก่อนแทนที่จริง เครื่องที่ตั้งค่าแล้วต้องเข้าระบบ Admin และยืนยันก่อนแทนที่ พร้อมสร้าง rollback backup ที่ตรึงไว้ ไม่รวมฐานข้อมูลสองเครื่องเข้าด้วยกัน

หลังสำเร็จ ใช้ชื่อผู้ดูแล/รหัสผ่านเดิม การตั้งเวลาที่นำเข้าจะพักไว้ก่อน ให้ตรวจปลายทางและเปิดการสำรองอัตโนมัติเมื่อพร้อม Mobile ใช้ token เดิมได้ถ้ายังไม่หมดอายุ มีอยู่ใน snapshot และ ERP ยังยอมรับ token นั้น

หากกู้จากไฟล์อย่างเดียว ให้เชื่อม Google Drive ใหม่ก่อนเปิดรอบนอกเครื่อง ระบบไม่ใช้ token เก่าจาก archive โดยอัตโนมัติ ส่วนการกู้ผ่าน Drive จะรักษา credentials ที่เจ้าของเพิ่งยืนยันและตรงกับ dataset/folder นั้น

ใบ client หรือ Hospital CA หมดอายุไม่ทำให้ข้อมูลสูญหาย ระบบจะนำเข้าในโหมดซ่อมแซมและยังไม่เปิด outbound ERP ใช้ CSR/ใบใหม่ที่คู่กับ **private key เดิม** ผ่านหน้ากู้คืน ไม่ต้องตั้งบัญชีหรือ encryption key ใหม่

## โอนตรงและสลับเครื่อง

1. เตรียม HTTPS ของ Gateway ใหม่และเส้นทางเครือข่ายก่อน เครื่องต้นทางต้องเข้าถึง URL ปลายทางได้ ใบ server ต้องครอบคลุมโดเมน/IP ที่ใช้ ระบบไม่ข้ามการตรวจ TLS โดยอัตโนมัติ
2. ที่ปลายทาง เปิด **รับการย้ายข้อมูล** ใน Admin หรือ Setup แล้วคัดลอกรหัสจับคู่ซึ่งมีอายุจำกัด
3. ที่ต้นทาง ระบุ HTTPS origin เช่น `https://gateway-new.example.org` กับรหัสนั้น หากเป็น IP ภายในให้เลือกอนุญาตเครือข่ายส่วนตัวอย่างชัดเจน
4. ส่งรอบแรกและตรวจปลายทาง เครื่องเดิมยังทำงานระหว่างเตรียม ถ้าขาดการเชื่อมต่อ ใช้ **ส่งต่อจากจุดค้าง**
5. เมื่อพร้อม กด **เก็บข้อมูลล่าสุดและเตรียมสลับเครื่อง** ต้นทางจะพักรับคำขอใหม่ หยุด workers และรอคำขอเดิมจบ ก่อนเก็บชุดสุดท้าย ส่งเฉพาะ encrypted objects ที่ปลายทางยังไม่มีและตรวจอีกครั้ง
6. ปลายทางแสดงว่าชุดสุดท้ายพร้อม จึงยืนยันเปิดใช้งานได้ จากนั้นสลับ reverse proxy/โดเมนไปเครื่องใหม่และตรวจ Mobile/ERP ก่อนปิดงานเครื่องเดิม

ควรใช้โดเมนสาธารณะเดิมเพื่อให้ Mobile เชื่อมต่อกลับที่ URL เดิม การโอนข้อมูลไม่ได้แก้ URL ภายใน Mobile หรือ DNS ให้เอง หากต้องเปลี่ยน DNS ให้เตรียม TTL/HTTPS/เส้นทางล่วงหน้า ระยะหยุดขึ้นกับข้อมูล ดิสก์ เครือข่ายและการกระจาย DNS ไม่มีการรับประกันจำนวนวินาทีคงที่

HTTP แบบ LAN เดิมยังใช้ Setup/Admin และนำเข้าไฟล์ได้ตามนโยบายที่อนุญาต การโอนตรงใช้ HTTPS; การมี VPN อย่างเดียวไม่ได้ปิดการตรวจใบ server

หลังพักต้นทาง ระบบ **ไม่เปิดกลับอัตโนมัติ** เมื่อ browser ปิด เชื่อมต่อหลุด หรือหมดเวลา ป้องกันสองเครื่องทำงานซ้อนกัน การยกเลิกปกติจะยืนยันกับปลายทางว่าไม่ได้เปิดใช้งาน หากปลายทางรับข้อมูลใหม่แล้ว ต้องสำรองข้อมูลปลายทางล่าสุดและเลือกชุดข้อมูลที่จะใช้ก่อนย้อนกลับ

## ตั้งเวลาและเก็บรักษา

- เปิด/พักการสำรองอัตโนมัติ โดยยังใช้ปุ่มสำรองตอนนี้ได้
- พักตารางจะปล่อยให้งานปัจจุบันทำจนจบ หากต้องหยุดงานที่กำลังทำให้กด **ยกเลิกงานนี้** แยกต่างหาก ไฟล์ที่ตรวจพร้อมแล้วไม่ถูกลบทิ้ง และเครื่องต้นทางที่พักเพื่อย้ายจะไม่กลับมาเปิดเอง
- เลือกทุกกี่นาที/ชั่วโมง รายวัน หรือวันในสัปดาห์ เขตเวลาเริ่มต้น `Asia/Bangkok`
- เลือกเก็บในเครื่อง หรือในเครื่องร่วมกับ Drive ส่วนตัว
- ปรับจำนวนชุดล่าสุด รายวัน รายสัปดาห์ รายเดือน หรือเก็บจนกว่าจะลบเอง แยกในเครื่อง/Drive
- ค่าเริ่มต้น: ในเครื่อง 3 ชุด; Drive ล่าสุด 24 ชุด + 7 รายวัน + 4 รายสัปดาห์ + 3 รายเดือน รอบเริ่มต้น 15 นาที
- ตรึงชุดย้ายเครื่อง/rollback ไว้จนตรวจระบบใหม่สำเร็จ แล้วปลดตรึงหรือลบผ่านหน้าเว็บ ระบบป้องกันชุดที่กำลังใช้/ดาวน์โหลดและสำเนาที่ดีชุดสุดท้าย
- การแก้นโยบายระหว่างจัดเก็บ/ลบไฟล์อาจได้ข้อความให้ลองใหม่ ไม่มีการแสดงว่าบันทึกแล้วแต่ไปใช้ค่าเก่าลบภายหลัง

สถานะในเครื่องกับนอกเครื่องแยกกัน แจ้งเตือนตามรอบที่เลือกและเวลาอัปโหลดสำเร็จจริง การตั้งทุก 15 นาทีไม่ได้รับประกันว่าอินเทอร์เน็ตจะส่งสำเร็จใน 15 นาที เมื่อเปลี่ยนรอบให้ปรับช่วงแจ้งเตือนตามด้วย

ทุกอัปโหลดตรวจ metadata/index ของ repository ส่วนการอ่านข้อมูลย้อนหลังจะหมุนตรวจวันละส่วน (30 ส่วน) และทดลอง restore ชุดล่าสุดทุก 7 วัน โดยทำเมื่อถึงกำหนดและมีการสำรองนอกเครื่องครั้งถัดไป จึงไม่ดาวน์โหลดทุกชุดเก่าซ้ำทุก 15 นาที ไฟล์ที่ทดลองกู้คืนจะถูกตรวจ key/ฐานข้อมูลแล้วลบจาก staging โดยไม่เปิด workers หรือแทนที่ข้อมูลจริง

เชื่อมบัญชีตาม [คู่มือ Google Drive](GOOGLE_DRIVE_BACKUP.md) เมื่อเชื่อม/เปลี่ยนบัญชีแล้วให้ดาวน์โหลดชุดกู้คืนฉบับล่าสุดอีกครั้ง การกู้จาก Drive บนเครื่องใหม่ใช้ชุดกู้คืน → ลงชื่อเข้า Google ด้วยเจ้าของบัญชี → เลือก snapshot แบบแบ่งหน้า ไม่ต้องมีเครื่องเก่าที่เสียอยู่

## งานค้างหลังการกู้คืน

งานแจ้งเตือนที่ยังไม่เสร็จจะถูกพักเพื่อไม่ส่งซ้ำโดยอัตโนมัติ เปิด **งานค้างหลังการกู้คืน** เพื่อตรวจและเลือกส่งต่อหรือยกเลิกอย่างชัดเจน งาน updater เก่าคงพักไว้และยกเลิกได้เท่านั้น ฟีเจอร์นี้ไม่เปิดโครงการอัปเดต ERP กลับมา

## คำสั่งฉุกเฉินเมื่อหน้าเว็บใช้ไม่ได้

ใช้ภายใน container ที่กำลังทำงาน คำสั่งติดต่อ private Unix socket และใช้ตัวสำรอง/กู้คืนชุดเดียวกับหน้าเว็บ ไม่เปิดฐานข้อมูลชุดที่สองหรือรีเซ็ตรหัสผ่าน

ส่งออกไฟล์และกุญแจไป **พาธใหม่สองพาธ** ใน volume ที่เขียนได้ (คำสั่งไม่เขียนทับไฟล์เดิม):

```bash
docker compose exec gateway /usr/local/bin/gateway backup-export /data/gateway.bundle /data/gateway-recovery-kit.json
docker cp erp-gateway:/data/gateway.bundle ./gateway.bundle
docker cp erp-gateway:/data/gateway-recovery-kit.json ./gateway-recovery-kit.json
```

ย้ายกุญแจไปที่เก็บแยกที่ปลอดภัย หลังตรวจว่าสำเนานอกเครื่องครบแล้วจึงลบไฟล์ส่งออกที่สร้างเองตามนโยบายของคุณ ไฟล์ใน `/data` ยังอยู่ในเครื่องเดียวกัน ไม่ใช่สำรองนอกเครื่อง

นำไฟล์เข้าเครื่องใหม่ด้วย `docker cp` แล้วรัน:

```bash
docker compose exec gateway /usr/local/bin/gateway backup-import /data/gateway.bundle /data/gateway-recovery-kit.json https://gateway.example.org
```

ไฟล์ต้องอ่านได้โดยผู้ใช้ Gateway (`65532` ใน image มาตรฐาน) ระวัง `docker cp` สร้างไฟล์เป็น root หากใช้ bind mount ให้จัด ownership/สิทธิ์จาก host ก่อน ไม่เปิดให้อ่านโดยทุกคน คำสั่งจะแสดงเวลา/จำนวนข้อมูลและถาม `RESTORE` กับ `SOURCE STOPPED` ก่อนแทนที่จริง

กรณีปลายทางเสีย/หมดอายุ session จนยกเลิกปกติไม่ได้ เครื่องต้นทางยังคงพักอยู่ หากได้ **หยุดปลายทางจริงแล้ว** และเลือกใช้ข้อมูลต้นทางเป็นชุดหลัก ให้รัน:

```bash
docker compose exec gateway /usr/local/bin/gateway migration-cancel-offline
```

ต้องยืนยัน `DESTINATION STOPPED` และ `USE SOURCE DATA` หากปลายทางเคยรับข้อมูลใหม่ ต้องเก็บ backup ปลายทางก่อนเลือกย้อนกลับ คำสั่งนี้ไม่รวมข้อมูลที่ต่างกัน และไม่ข้ามคำตอบที่ปลายทางยืนยันว่ากำลัง active อยู่

## ข้อผิดพลาดและขอบเขตการย้อนกลับ

- กุญแจผิด ไฟล์ไม่ครบ checksum ผิด หรือดิสก์ไม่พอ: หยุดก่อนเปลี่ยนข้อมูลที่ใช้งาน
- หลุดระหว่างโอน: เก็บส่วนที่ตรวจแล้ว ใช้ส่งต่อได้และตรวจ session/base ก่อนใช้
- กู้คืนล้มก่อนเปิดใช้งาน: journal กู้ฐานข้อมูล/config/key ชุดเดิมให้ตรงกันและเปิดบริการเดิมเมื่อทำได้
- หลังปลายทางเปิดรับข้อมูลแล้ว: ไม่ย้อนกลับอัตโนมัติ ใช้ขั้นตอนกู้คืนใหม่และสำรองข้อมูลล่าสุดก่อน
- ลืมรหัส Admin: ใช้ `setup-password` ตาม README ข้อมูลและกุญแจไม่หาย แต่ไม่สามารถใช้แทนกุญแจเปิด backup ได้
